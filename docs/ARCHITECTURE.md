# 架构与同步协议

## 三层结构

界面通过有限的 Tauri 命令调用本地数据和同步功能。SQLite 和 HTTP 请求都在 Rust 中处理；界面不直接持有网络权限或任意文件访问权限。`qingnote-core` 独立于桌面运行时，可以不安装 GTK 运行其测试。

`Arc<Mutex<Store>>` 串行处理本地 SQLite 操作。锁只用于本地读写，发出网络请求前释放，因此同步超时不会锁住正在编辑的便签。一个异步锁保证同一进程不并发执行同步或变更同步配置。

## 本地数据

只使用三张表：

- `revisions`：不可变版本和是否已上传。
- `drafts`：每张便签最多一个未封存的可合并草稿。
- `settings`：WebDAV 地址、账号、窗口状态、请求预算；不存密码。

SQLite 开启 WAL 和 FULL synchronous。保存正文与版本状态在一个本地事务中完成。版本 ID 和便签 ID 使用 UUID；客户端保存必须提供编辑时的版本，陈旧窗口不能静默覆盖较新的本机输入。

## WebDAV 文件

```text
QingNote/
  v1/
    <revision-uuid>.json
```

每个对象含 `schema`、`id`、`noteId`、`parents`、`content`、`createdAt`、`updatedAt`。正文、颜色、归档与删除状态属于 `content`。窗口布局不参与同步。

0.1.1 的折叠、透明度、字体、字号和 Markdown 预览偏好复用 `settings` 中每个窗口的记录，不新增表。折叠只改变原生窗口高度，单独保留展开时的宽高。Markdown 源码仍是原有 `content.text`；预览由 Marked 解析、DOMPurify 过滤，仅额外允许无属性的 `<u>` 标签，不加载图片或导航链接。

独立标题使用可选的 `content.title`；缺少标题的历史记录按空标题读取，序列化时省略空标题，避免改变历史不可变对象。标题参与版本比较、同步、备份与冲突处理。旧客户端拒绝未知字段，因此使用独立标题前必须更新全部同步设备，不支持新旧客户端混用这一功能。

`RichEditor.svelte` 封装 Tiptap / ProseMirror 的排版编辑和选区，`rich-text.ts` 配置 Markdown 转换、下划线兼容及转换前后校验；`TextTools.svelte` 是菜单内复用的格式控件。工具不常驻正文，原生右键菜单通过保存的选区操作编辑器。富文本文档只在前端内存中存在，正文仍保存为 `content.text` Markdown。

初始加载、切换模式和外部刷新不触发正文改写，只有真正的文档编辑才序列化。图片、非允许 HTML 等在解析前拦截；对可处理内容检查往返后的可见文本、结构、格式、任务状态和链接。无法可靠转换时只读显示并保留源码，而不是自动删减。HTML 粘贴过滤网络加载属性、图片、脚本等，链接不在 WebView 中导航。下划线继续输出 `<u>`，而不是编辑器内核默认的另一种扩展语法。

源码模式的格式工具仍通过 `insertText` 修改选区以保留撤销历史，不支持时降级为 `setRangeText`；排版模式的撤销、输入法和选区由 ProseMirror 管理。

先用 PROPFIND Depth:1 列出版本文件，下载本机未知版本，再封存草稿并上传远端没有的版本。一次最多下载 24 个、上传 12 个；本机持久化请求预算跨重启生效。每个请求有连接和总超时，响应体有大小上限。

未尝试上传的草稿可合并；一旦封存，即便上传失败也不重写同一对象。上传使用 `If-None-Match: *`；返回 412 时读取对象并校验内容。即使服务商不实现条件写，也只会重发同一 UUID 下的相同内容。文件列表只接受当前目录、同源的 UUID JSON 文件。

## 并发修改

版本通过 `parents` 形成关系。没有被其他版本引用的版本就是当前分支末端。只有一个末端时直接显示；有多个时显示冲突提示，并保留各分支。

例如 A、B 都从版本 1 编辑，产生 `2A → 1` 和 `2B → 1`。两份内容都保留。用户确认合并后，版本 3 同时引用 2A 与 2B，冲突解除。

时间只用于稳定排序，不能决定是否丢弃版本。删除也是普通版本，不物理删除云端文件，因此一端删除、另一端离线编辑仍能展示冲突。乱序下载支持缺失的父版本；后续下载会补齐。

## 可读性和范围

没有通用同步引擎、CRDT 框架或实时协作层。协议是面向个人便签的最小不可变版本集合。代价是历史数据持续增长，不适合大规模文档、附件或频繁协作。第一版不做历史压缩，以免引入离线设备回收协议。

导入备份合并版本，不替换资料库。导出前封存草稿，保证导出的版本不会随后发生原地变化。

## 安全边界

- 仅允许用户填写 HTTPS WebDAV 地址，不跟随重定向，不忽略 TLS 错误。
- 网络凭据仅在 Rust 侧请求时使用，保存到 OS 凭据库；不可用时明确降级为当前会话。
- Linux 应用资料目录权限设为 0700；备份使用临时文件写入完成后替换目标文件。
- 全部前端脚本、样式和图标本地打包，不使用远程字体、CDN 或外部脚本。
- 没有端到端加密；不适合把云服务视为不可信存储的场景。

## 发布前人工验收

自动测试不能代替以下实机检查：Windows 多窗口与输入法；Linux Wayland 各桌面环境；坚果云真实账号的连接、跨设备同步、限流；系统凭据库锁定和解锁；安装、升级、卸载后资料保留。
